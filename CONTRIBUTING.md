# Contributing

TLMS is a public, commercially licensed project. Public visibility does not automatically authorize contributions, production use or redistribution. Read LICENSE, COMMERCIAL-LICENSING.md and SECURITY.md before engaging.

## Current contribution status

External code contributions are not yet being accepted while Tinlance finalizes its contributor rights policy. Issues describing reproducible defects, documentation corrections and carefully scoped feature proposals are welcome.

Do not submit confidential information, credentials, customer data, copied proprietary code or material whose licence is unclear.

## Engineering requirements

When code contributions open:

1. Create a focused branch and pull request.
2. Add or update tests for every behavior change.
3. Follow test-driven development: failing test, minimal implementation, refactor, full verification.
4. Run formatting, static analysis, unit and integration tests.
5. Document security, migration, API and compatibility implications.
6. Keep changes small, reviewable and independently reversible.
7. Never disable or weaken tests to obtain a green workflow.

## Pull request checklist

- [ ] Scope and acceptance criteria are clear.
- [ ] Tests cover normal, boundary and failure behavior.
- [ ] No secrets, private data or generated build artifacts are included.
- [ ] Documentation and changelog are updated where applicable.
- [ ] Dependency and licence implications are disclosed.
- [ ] Security and backward-compatibility implications are addressed.

A pull request is not accepted until reviewed and merged by an authorized maintainer under the project's contribution agreement.
